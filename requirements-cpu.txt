# CPU-only torch pin (install-friction win #1).
#
# sentence-transformers pulls torch transitively, and on Linux the DEFAULT PyPI
# torch wheel bundles the full CUDA toolkit (~2GB) that this CPU-only embedding
# service never uses. Installing torch FIRST from PyTorch's CPU index pins the
# same torch VERSION with the CPU build, so the subsequent `pip install .`
# resolves torch as already-satisfied and pulls no CUDA payload.
#
# This is packaging only -- SAME torch version, SAME CPU compute backend, SAME
# embeddings (byte-identical; validated against the CUDA-wheel build). Index
# URLs cannot be expressed in pyproject's [project.dependencies], so the pin
# lives here and is used by both the Dockerfile and the local/pip path:
#
#   pip install -r requirements-cpu.txt   # CPU torch, from the CPU index
#   pip install .                         # everything else, from PyPI
#
# Keep the version equal to whatever `pip install .` would otherwise resolve
# (currently torch 2.13.0); the ONLY difference must be the +cpu local build,
# never the version number.
--index-url https://download.pytorch.org/whl/cpu
torch==2.13.0
